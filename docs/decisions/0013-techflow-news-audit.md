# ADR-0013：TechFlow 逐条新闻审计采用独立页面、确定性三结果和本地私有留存

状态：`ACCEPTED`

生效日期：2026-08-23

生效配置：`0.3.2`

## 背景

首页只展示进入宏观风险路径的最新事件，无法让用户核对程序是否持续采集，也无法看到被规则过滤的普通新闻。用户要求看到程序实际观察到的每条 TechFlow 快讯、逐条判断与官网核对入口，同时保持首页只回答当前是否需要操作。

## 选择

1. 新增独立 `/news` 页面，不把完整新闻列表平铺到首页。
2. “每一条”只指功能启用后公开列表 adapter 实际观察到的独立 `source_item_id` 及其 revision；不声称补齐停机、漏页或启用前历史。
3. 每次首次接收或内容 revision 都冻结当时的四步判断，最终结果互斥为“进入风险观察 / 未进入风险观察 / 需要人工复核”。规则升级不得覆盖旧判断，只能产生独立 replay 结果。
4. 本地以 `0600` append-only JSONL 保存 180 天；保存规范化元数据、链接、最多 600 字摘要和判断，不保存完整正文，`data/` 继续由 Git 排除。
5. TechFlow 超过 30 秒没有成功语义解析即失效；fetch 与 body 共用显式截止。页面心跳与“是否出现新新闻”分开显示。
6. 不增加第二新闻源、付费源、LLM 热路径、RPC、钱包或执行能力。

## 理由

独立页面同时保护首页决策效率和审计完整性。确定性规则可以复现每次判断，三结果避免把“不知道”伪装成“未触发”。本地私有留存支持重启核对，又不把运行新闻数据发布到公开仓库。30 秒 freshness 使“没有新坏消息”必须建立在采集仍然存活的事实之上。

## 代价与风险

- 单一公开列表没有完整历史或 SLA；页面只能诚实展示实际观察范围。
- 关键词规则可能误分隐含或新表达；人工核对和历史 replay 仍然必要。
- 180 天后原始审计记录会被原子清理；长期结论应保存聚合证据而不是完整正文。
- freshness 语义变化使 v0.3.2 Shadow 必须使用新 epoch，不能与 v0.3.1 连续时间混算。

## 可逆性

页面信息架构、保留天数和关键词规则可以经新配置或新规则版本调整。历史判断、旧 journal 和已记录的 gap 不可覆盖；删除旧证据需要单独授权。
